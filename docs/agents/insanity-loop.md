# Insanity Loop

Repeating an approach that has already failed, in the expectation that this attempt will land. When the same failure recurs, the recovery is a hard reset to evidence — never another variation on the attempt that failed.

Applies to every turn, both views. This is a Process topic — it governs all other work.

## When this topic applies

A hard reset is due the moment the same failure comes back: a second attempt rejected for the reason the first was, the same correction issued twice, or an edit discarded again after a change aimed at a cause you inferred rather than read.

One failure is ordinary work. The same failure twice means the attempt is being varied against a theory instead of re-derived from evidence, and no further variation will find the answer.

## Hard reset

Discard all previous reasoning, explanations, assumptions, inferred motives, and proposed solutions. They are untrusted (see [modes](modes.md)). Do not invent why the user requested the work, and do not invent why an edit was rejected.

The reset falls on the reasoning, never on the work. What the files hold and what the user said both stand — and are re-read rather than remembered (see [loop](loop.md)).

## A correction is not a theory

Treat the latest user correction literally. It is not evidence for a new theory. Use only facts established by the latest user instruction, the current repository state, the workplan, and the rules actually read.

A rejection or revert means exactly what `docs/agents/precedence.md` states: a compliance mismatch. It does not prove that the entire approach, every edit, the task, or the user’s intent was wrong.

## Recover element by element

Review prior work element by element against the applicable requirements:

- preserve elements that satisfy the rules;
- identify the specific element or elements that fail;
- correct only those elements;
- do not change valid work merely because another element failed;
- do not repeat an element merely because it appeared in a rejected attempt;
- do not replace an uncertain diagnosis with speculation.

Do not defend prior work, and do not globally discard valid work. A rejected attempt is a mixture: the elements that complied still comply, and finding the one that did not is the whole of the recovery.

## When nothing resolves

If the exact compliant action cannot be established from the evidence and the rules, state that plainly and halt. An action you cannot ground is the next iteration of the loop, not an escape from it.

## Precedence

This topic outranks the workplan. A node step that has you retry an approach that already failed, discard completed compliant work because a later element failed, or proceed on an inferred cause rather than a read one is defective — comply with this topic and report the discrepancy.
